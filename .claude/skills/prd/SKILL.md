## PRD 기반 자동 워크플로우

**자동 호출:** 사용자가 PRD/요구사항 문서를 전달했을 때

### Phase 1: PRD 분석 & 질문 (한 번만)

1. **PRD 읽기:** 문서 전체 스캔
2. **모호한 점 추출:** 설계 선택지가 여러 가지인 부분 찾기
   - 예: 인증 방식 (JWT vs. Session)
   - 예: 데이터 보관 위치 (localStorage vs. cookie)
   - 예: 통합 테스트 필요 여부
3. **한 번에 물어보기:** 최대 3개 질문 (답변 후 진행, 다시 안 묻음)
4. **플랜 저장:** `docs/plans/[날짜]-[기능명].md` 체크박스 형식으로 저장
5. **사용자 확인:** "이 플랜 괜찮나?" 1회 확인 → 승인 or 수정 지점 지시

### Phase 2: 자동 구현 (사용자 개입 0)

- 각 태스크별 구현
- 작은 단위로 커밋 (feat:, fix:, refactor: 접두사)
- 각 단계 후 `npm run build && npm run test` 실행
- 실패 시 자동 중단 + 에러 보고

### Phase 3: 자동 리뷰

- 구현 완료 후 `/review` 체크리스트 실행 (1회, 수동 개입 없음)
- 통과 여부 보고

### Phase 4: 자동 학습 기록

- `/learn` 실행 → `docs/learnings.md`에 3줄 기록
- 완료 보고

---

## 사용자 개입 지점

1. **PRD 전달** → Claude가 받음
2. **질문 답변** (최대 3개) → 플랜 저장
3. **플랜 확인** (1회) → "좋아"하면 자동 진행
4. **완료 보고** → 결과 확인

---

## 실패 케이스

- 빌드 실패 → 에러 출력 + 사용자에게 수정 요청
- 리뷰 불통과 → 지적 사항 + 수정 요청
- 복잡한 버그 발생 → `/debug` 스킬 자동 호출
